# Decisions

One row per real choice. Newest at the bottom.

| Date | Decision | Alternatives | Why | Evidence |
|---|---|---|---|---|
| 2026-10-25 | `uv` manages Python, dependencies and the lock file | pip + venv; Poetry; PDM | One tool installs Python 3.12, resolves and locks dependencies, and runs commands. Fast in CI. | `uv.lock`, `make setup` |
| 2026-10-25 | `ruff` for lint and format, `mypy` in strict mode for types | flake8 + black + isort; pyright | ruff replaces three tools and runs in well under a second. Strict mypy catches wrong types in the checks before the tests do. | `make lint`, `pyproject.toml` |
| 2026-10-25 | One Postgres with pgvector for text, vectors, keyword search, XBRL facts and eval results | Postgres plus a separate vector store (Chroma, Pinecone); SQLite + FAISS | One database keeps joins, transactions and backups simple and fits Neon's free 1 GB plan. pgvector covers vector search; `tsvector` covers keyword search. | `docker-compose.yml` |
| 2026-10-25 | `edgartools` for EDGAR access (filing lists, documents, 10-K Items) | `sec-edgar-downloader`; hand-written parsing of the EDGAR indexes | It already handles filing indexes and Item extraction. Our own rate-limited, cached client stays in front of every raw download. Version pinned on day 3. | `filingcheck/ingest/filings.py` (day 3) |
| 2026-10-25 | The SEC contact email lives only in `.env` (`SEC_CONTACT_EMAIL`), never in a committed file | Writing the email into the code or a committed config file | The repo is public. The SEC needs the email in the User-Agent header at request time, not in the source. | `.env.example` |
| 2026-10-25 | SEC requests are spaced at least 1/8 s apart by one limiter shared across the process | A token bucket that allows bursts; one limiter per client | A bucket that refills can pass more than 8 requests inside one second. Fixed spacing keeps every one-second window at 8 or fewer, under the SEC's limit of 10. | `tests/ingest/test_sec_client.py` |
| 2026-10-25 | Disk cache of raw response bytes at `data/cache/<sha1(url)>`, written atomically, with a `cache_only` mode | Caching parsed JSON; `requests-cache` | The same URL always maps to the same file, nothing is parsed before it is saved, and an interrupted run never leaves half a file. `cache_only` lets tests and the live app prove they never reach sec.gov. | `filingcheck/ingest/sec_client.py` |
| 2026-10-25 | Retry 429, 5xx and network errors up to 5 times, waiting 0.5, 1, 2, 4 and 8 s; other 4xx fail at once | Retrying every error; honoring `Retry-After` | 429 and 5xx are temporary; a 404 will not fix itself. `Retry-After` can be added if the SEC starts sending it. | `tests/ingest/test_sec_client.py` |
| 2026-10-25 | `data/companies.yaml` is written by code; CIKs are quoted 10-digit strings | Editing CIKs by hand; keeping hand-written comments in the file | One source of truth that can be re-run. Quoting keeps the leading zeros and stops YAML readers from reading a CIK as a number, or as octal when it has only digits 0–7. The field meanings live in the file header. | `data/companies.yaml` |
| 2026-10-25 | Tests fake the network with `httpx.MockTransport` | `respx` | Built into httpx, so one less dependency. | `tests/ingest/` |
| 2026-10-25 | Replace BlackRock (BLK) with Moody's (MCO) | Follow both of BlackRock's CIKs; keep BLK with fewer years | BlackRock re-registered in 2024: its FY2025 10-K is under CIK 0002012383 and its FY2023 10-K under the old CIK 0001364742 (now "BlackRock Finance, Inc."). Following both would add code to the company checks for no gain. Moody's is based in New York, files under one CIK, and pairs with S&P Global (both ratings companies) for comparison questions. Six banks already cover the bank revenue rule. | `data/companies.yaml` |
| 2026-10-25 | The contact-email check runs when a `SecClient` is created, not when the module is imported | Failing at import | The live app imports the package but only reads the cache, so it must not need the SEC email. Ingest still fails loudly before its first request. | `tests/ingest/test_sec_client.py` |
| 2026-10-25 | Documents decode as UTF-8, then as the charset they declare, then as UTF-8 with replacement characters | Strict UTF-8; guessing an encoding | Older EDGAR HTML is not always UTF-8, and one bad byte should not stop ingest. | `tests/ingest/test_sec_client.py` |
| 2026-10-25 | Filing lists come from the SEC submissions JSON through `SecClient`, not from edgartools (this replaces the "filing lists" part of the edgartools entry above) | edgartools' filing index | edgartools sends its own requests, outside our rate limiter and cache, and every sec.gov request must go through `SecClient`. The submissions JSON has every field needed: form, accession number, dates, period of report and primary document. edgartools may still parse 10-K Items from the cached HTML; its version is pinned when it is added. | `filingcheck/ingest/filings.py` |
| 2026-10-25 | Each company's latest three fiscal years; the original 10-K wins over a 10-K/A, which is used only when the original is missing | Calendar-year cutoffs; the latest amendment | Three years give FinanceBench questions more to match. Amendments often restate only part of a filing. All 75 chosen filings are original 10-Ks. | `data/manifest.json` |
| 2026-10-25 | The fiscal year is the DocumentFiscalYearFocus tagged in the 10-K's inline XBRL; without it, the calendar year the period ends in (a 52/53-week year that ends in the first 7 days of the next month counts as the month before) | The `fy` field of companyfacts; fetching each filing's XBRL instance | The tag is in the primary document we download anyway, so it costs no extra request. All 75 filings carry it, and it matched the period-based year in every case. | `data/manifest.json` |
| 2026-10-25 | Once `data/manifest.json` exists, `make ingest` reuses the filings it pins; `--reselect` chooses again | Choosing again on every run | New 10-Ks keep arriving (Apple's FY2026 10-K is due within days), so choosing again would quietly change the dataset under the evaluation. | `filingcheck/ingest/__main__.py` |
| 2026-10-25 | Re-pin the manifest once, in early November 2026 (`filings --reselect`), to add Apple's FY2026 10-K, then freeze it | Freezing now without Apple's latest year; re-pinning whenever a new 10-K appears | Apple's FY2026 10-K is due within days of this choice; after that, every company has its latest three years and the dataset stops moving. | `Makefile` |
| 2026-10-25 | Tests build the expected User-Agent from `SEC_CONTACT_EMAIL` instead of a fixed address | A hardcoded test address | The suite then passes under any contact email set in the environment. | `tests/ingest/test_sec_client.py` |
| 2026-10-25 | Find the five Items with edgartools 5.62.1 (pinned), used offline on the downloaded HTML; a heading splitter is the fallback, and the method is recorded per Item | edgartools' download functions; only our own splitter | edgartools' parser handles the many 10-K layouts; its download functions would bypass our rate limiter and cache, so they are never called (a test fails on any HTTP request). It sits in a separate `ingest` dependency group, so the live app installs without it. On the real data it found 369 of 375 Items; the other 6 came from Exhibit 13. | `data/sections/summary.json` |
| 2026-10-25 | When Item 7 or 8 is under 2,000 characters, read the filing's index page (`<accession>-index.htm`), download any EX-13 exhibit, and cut Items 7 and 8 from it at the auditor's report | `index.json`; treating IBM as a special case | `index.json` lists file names only, and an Exhibit 13 file name need not say so (IBM's is `ibm-20251231_d2.htm`); the index page gives each document's type. Exhibits are pinned in the manifest. Result: IBM's Items 7 and 8 in all three years. Johnson & Johnson, Pfizer and Verizon were checked: their Items 7 and 8 are complete in the 10-K itself. | `data/manifest.json` |
| 2026-10-25 | A short Item 7A is reported, not fixed | Fetching more documents for it | In all 30 cases (11 companies, mostly banks) Item 7A is a one-line pointer to a market-risk section inside Item 7, which is already indexed. | `data/sections/summary.json` |
| 2026-10-25 | Netflix and Nvidia (6 filings): Item 8 is listed as a gap for now | Guessing where their statements start | Their Item 8 points to statements elsewhere in the same 10-K (Nvidia: under Item 15; Netflix: after Part IV), not to an exhibit. How to cut them out is still to be decided. | `data/sections/summary.json` |
| 2026-10-25 | Chunks of at most 1,100 characters with about 200 overlapping; cut at a paragraph break, else a sentence end, else between words; never across Items; offsets point into the cleaned Item text | Fixed-size windows; token-based chunks | Paragraph-sized chunks are specific but still read as whole thoughts, and offsets make every chunk traceable. | `filingcheck/ingest/chunking.py` |
| 2026-10-25 | Noise rules: drop chunks under 200 characters, chunks that are more than half digits and punctuation, and contents lists (3 or more "Item ... page" lines, or 10 or more lines of which 40% are 3 characters or fewer); before chunking, remove short lines that repeat 5 or more times in an Item (page headers and footers) and turn no-break and other Unicode spaces into plain spaces | Keeping tables as text; dropping by keyword | Tables are answered from XBRL numbers, not text search. Real data: 2,481 table chunks, 6 contents lists and 3 short chunks dropped; 18,513 no-break spaces normalized. | `tests/ingest/test_chunking.py` |
| 2026-10-25 | Keep 51,178 chunks, below the earlier rough estimate of 60,000 to 200,000 | Smaller chunks to reach the estimate | The estimate came before any data. The five Items hold 38.6 million characters, which at a 900-character step gives about 43,000 chunks before IBM's exhibits and minus noise. The chunk size is chosen for retrieval quality, not to hit a count. | `data/chunks.jsonl` |
| 2026-10-25 | When Item 8 only points to statements elsewhere in the same 10-K and there is no Exhibit 13, cut Item 8 from the auditor's report on the financial statements to the exhibit index, the signatures or Item 16, whichever comes first (method "relocated"); this resolves the gap recorded above | Starting at the first auditor's report; ending at the Item 15 heading | Netflix files a separate report on internal control in Item 9A, before its statements, so the first auditor's report is the wrong one, and Item 15 comes before the statements in both companies. The report on the statements is the one with an "Opinion on the Financial Statements" (or, failing that, its addressee), judged only by the text before the next such heading so that a contents line cannot borrow it. Result: Netflix's and Nvidia's Item 8 in all six filings (74,000 to 97,000 characters each), checked by slow tests on the real filings; 0 filings with gaps. | `tests/ingest/test_real_filing.py` |
